What the benchmark names mean

For same-claim rows, size is the number of signers. For distinct-claim rows, it is the number of signer-and-message pairs.

Same-claim aggregation
Many independent signers sign the same message. LeanVM checks those signatures in the zkVM and produces a proof; Lighthouse combines the BLS signatures into one signature.
Same-claim verification
Checks the LeanVM proof or aggregate BLS signature against that one message and the complete set of signers.
Distinct-claim aggregation
Combines signatures when each signer signed a different message.
Distinct-claim verification
Checks the aggregate against every signer-and-message pair. The “conceptual” Lighthouse row uses its non-production aggregate-verify path.
Independent signature verification
Checks a set of separate signer-and-message tuples. LeanVM verifies each raw XMSS signature; Lighthouse verifies the equivalent BLS tuples together with its production batch-verification API.
Proof size and signature size
The LeanVM proof size is the serialized zkVM proof produced by aggregation. The Lighthouse value is the serialized aggregate BLS signature.
Serialized artifact sizes
Storage or wire-encoding sizes, not in-memory object sizes. The LeanVM secret key is generated for the benchmark’s 16 signing slots.
Suite peak RSS
The maximum physical memory used by the complete slow-suite process. It is not measured separately for each row.
